## How It Works

1. **Startup & Authentication (`TopSecret`, `Password`)**
   The application begins in `TopSecret.java`. It instantiates `Password` to handle user authentication against the `credentials.cip` file. If no credentials exist, it guides the user to create the first account (which becomes admin). The `-w` flag launches the web interface; otherwise the terminal UI starts.

2. **Terminal Interaction (`UserInterface`, `TerminalView`)**
   Once authenticated, `UserInterface` presents a menu-driven terminal interface. It supports browsing missions, agents, facilities, sending/viewing messages, and (for admins) reviewing the audit log. All output is formatted through `TerminalView`. Command-line args `-p` (change password) and `-u` (create user) are also handled.

3. **Web Interface (`WebController`, `HTMLView`, `SessionManager`)**
   `WebController` starts an HTTP server on port 3002. It manages cookie-based sessions via `SessionManager`, protects all pages with login, and renders HTML via `HTMLView`. Admin-only pages include user management and audit log review. All pages include a persistent navigation bar with logout. Create and edit forms for all entity types are available to admin users. A messaging center is accessible to all logged-in users.

4. **Core Controller (`ProjectControl`)**
   `ProjectControl` is the central coordinator for all business logic. It delegates database operations to `DatabaseManager`, file operations to `FileHandler`/`Cipher`, and records all significant actions to `AuditLog`.

5. **Data Layer (`DatabaseManager`, `FileHandler`, `Cipher`, `AuditLog`)**
   - **`DatabaseManager`**: Connects to SQLite and manages tables for countries, facilities, agents, missions, mission-agent assignments, agent messages, and the audit log. Implements `SearchFeature` for keyword-based mission search.
   - **`FileHandler`**: Reads flat files from the `data/` directory with path-traversal protection.
   - **`Cipher`**: Builds a decryption map from a key file and decrypts substitution-ciphered strings.
   - **`AuditLog`**: Records all READ, CREATE, and UPDATE events with timestamps into the `audit_log` table.

6. **Entity Models (`Mission`, `Agent`, `Facility`, `Country`, `Message`)**
   Data classes representing the core domain entities. `Mission` supports mutable fields and agent-list management. `Facility` now includes an optional country association via `Country`. `Message` represents inter-agent communications and tracks read status.

7. **View Layer (`View`, `TerminalView`, `HTMLView`)**
   The `View` interface defines rendering contracts. `TerminalView` formats output for the console. `HTMLView` generates HTML for the web interface, including login pages, lists, detail pages with linked related entities, create/edit forms, a messaging center, and admin pages.
